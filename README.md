# ЦенаРадар (Android)

Нативное Android-приложение для поиска товаров на Wildberries и Ozon, сравнения найденных цен и отслеживания выбранных предложений. При достижении заданной цены или снижении стоимости приложение отправляет уведомление со ссылкой на карточку товара.

## Что умеет приложение

- Ищет по названию или вставленной ссылке на WB/Ozon; площадки можно включать по отдельности или обе сразу.
- Сортирует распознанные предложения по цене и позволяет добавить конкретную карточку в список наблюдения.
- Для каждого товара можно задать цену-порог. Без порога уведомление приходит при снижении относительно предыдущей успешной проверки; с порогом — когда цена достигнет указанного значения. Первичная проверка товара с заданным порогом тоже может вызвать уведомление.
- Проверяет список вручную и планирует фоновую проверку примерно раз в 24 часа через Android WorkManager. Android может отложить её из-за энергосбережения; это не точное расписание.
- При запуске проверяет GitHub Releases на наличие новой версии и предлагает скачать APK. Установка всегда подтверждается системным установщиком Android — обычное приложение не может незаметно обновить само себя.

## Сборка и нумерация

Workflow находится в `.github/workflows/android.yml`. GitHub Actions собирает APK при push в любую ветку, pull request и ручном запуске workflow. Каждая попытка сборки получает уникальный номер: `run_number * 1000 + run_attempt`; версия приложения и имя release-тега также содержат номер запуска и попытки.

APK с постоянной подписью появляется во вкладке **Actions → Artifacts** и доступен 30 дней. GitHub Release автоматически публикуется только при push в `main` и только когда настроен постоянный ключ. В release APK всегда называется `sales-master.apk` — по этому имени приложение находит обновление.

Если постоянный ключ ещё не настроен, Actions только компилирует debug-вариант для проверки кода и **не публикует APK**. На GitHub Actions временный debug-ключ может меняться между запусками, поэтому такой APK нельзя использовать для обновления предыдущей debug-сборки.

## Настройка постоянной подписи

Ключ подписи нельзя хранить в репозитории. Создайте его один раз на доверенном компьютере и сохраните защищённую резервную копию вне GitHub:

```bash
keytool -genkeypair -v \
  -keystore sales-master-release.jks \
  -alias sales-master \
  -keyalg RSA -keysize 4096 -validity 10000
```

Закодируйте файл в Base64 одной строкой. На Linux:

```bash
base64 -w 0 sales-master-release.jks
```

На macOS:

```bash
base64 < sales-master-release.jks | tr -d '\n'
```

В GitHub откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте четыре секрета:

| Secret | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | Base64-содержимое `.jks` |
| `ANDROID_KEY_ALIAS` | `sales-master` (или заданный при создании alias) |
| `ANDROID_STORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_PASSWORD` | пароль ключа |

Не меняйте и не теряйте ключ после публикации первой версии: Android разрешит обновление установленного приложения только APK, подписанному тем же ключом. Текущие GitHub debug-сборки подписываются временным ключом runner и не подходят для установки поверх предыдущей debug-сборки. Вариант `.debug` также имеет отдельный ID пакета; первый production APK устанавливается отдельно. После его установки новые production APK с тем же постоянным ключом обновляются поверх. Если рядом останется тестовая `.debug`-версия, её можно удалить отдельно.

## GitHub Releases и автообновление

Приложение обращается к публичному GitHub API репозитория `zigorminsk-debug/sales-master` и проверяет последний стабильный release при запуске. Чтобы появились обновления для приложения, добавьте изменения в `main`, включите указанные signing secrets и дождитесь успешного workflow. После появления нового release приложение покажет кнопку загрузки. Для установки нужно разрешить этому приложению установку APK (Android может открыть системные настройки) и подтвердить обновление в установщике.

## Ограничения источников цен

Приложение использует доступные веб-эндпоинты каталогов площадок без входа в аккаунт. Это не официальные пользовательские API: площадки могут менять формат ответов, ограничивать запросы или временно не отдавать цены. В таких случаях приложение покажет ошибку площадки; персональные скидки, цены после авторизации, доставка и наличие в конкретном регионе не гарантируются. Фоновые уведомления требуют разрешения Android на уведомления.

## Локальная сборка

Нужны JDK 17, Android SDK с платформой 35 и Gradle 8.10.2. Пример:

```bash
gradle :app:assembleDebug
```

Для локальной release-сборки передайте `buildNumber`/`appVersion` и установите signing-переменные окружения `ANDROID_KEYSTORE_PATH`, `ANDROID_KEY_ALIAS`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`. Файл ключа не добавляйте в Git.
